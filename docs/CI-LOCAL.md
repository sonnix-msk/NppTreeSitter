# Local reproduction of `CI_build` for PRs #9, #10, #11

The GitHub Actions runs created for these pull requests never executed a single
step: GitHub requires a maintainer to approve workflow runs coming from a fork,
nobody approved, and the runs **expired after 30 days** with

> This workflow run required approval but was not approved before it expired.

So both the workflow run (`/actions/runs/<id>/jobs` returns `total_count: 0`)
and the commit check-runs (`total_count: 0`) contain **no jobs and no logs** —
the `failure` conclusion says nothing about this code.

To still give a reviewable signal, the same steps were executed locally, in the
same order and with the same arguments as `.github/workflows/CI_build.yml`.

## ARM64 — not verified locally

This host has no ARM64 MSVC toolchain (`VC\Tools\MSVC\14.51.36231\bin\Hostx64\arm64`
and `MSBuild\Microsoft\VC\v180\Platforms\ARM64` are absent), so MSBuild falls back
to `v143` and stops with `MSB8020`. `windows-latest` ships the ARM64 tools, so the
CI leg should build there — but it cannot be demonstrated from this machine.

The diffs in these PRs touch no architecture-specific code: `#11` and `#10` are
`src/dllmain.cpp`, `#9` is `src/TreeSitterLexer.cpp` — plain C++/Win32 API calls,
no intrinsics, no inline assembly, no pointer-size assumptions.

## Reproduce

```powershell
$msb = 'C:\Program Files (x86)\Microsoft Visual Studio\18\BuildTools\MSBuild\Current\Bin\MSBuild.exe'
$msb NppTreeSitter.vcxproj /m /p:configuration=Debug   /p:platform=x64
$msb NppTreeSitter.vcxproj /m /p:configuration=Release /p:platform=x64
.\grammars\build-grammars.ps1 -Platform x64 -Configuration Release
.\package-release.ps1 -Platform x64 -Configuration Release

# same for /p:platform=Win32 and -Platform Win32
```

Two grammars (`sql`, `elisp`) have no committed `parser.c` and are generated by
`npm exec --yes tree-sitter-cli -- generate`; the first attempt failed with
`ECONNRESET` from `registry.npmjs.org` and the tree-sitter-cli postinstall left a
`tree-sitter.exe`-less package behind. Clearing `npm-cache\_npx` and re-running
fixed it. That is local network flakiness, not a repository problem.
